# 构想：类豆包的开源个人 AI 工具（x-gulu）

> 交付物 00 · 由 /flow-brainstorm 产出 · 下游：/flow-grill（产出 01-需求.md）· 可选留档

## 问题复述

"类似豆包的开源工具"范围太大无法直接开工，需要在多个差异明显的切入方向中发散再收敛，确定先做什么、按什么顺序做。

**已知约束**（用户输入）：

- BS 架构，Go 后端 + TypeScript 前端
- 开源个人工具，无需登录

## 候选方向（发散）

| # | 方向 | 一句话说明 | 视角 |
|---|------|------------|------|
| 1 | 极简 Chat 克隆 | 多会话聊天界面，接多家 LLM API，Markdown 渲染 + 本地历史存储 | 最小可行 |
| 2 | AI 搜索引擎 | 问题 → 联网抓取 → 流式总结 + 引用来源 | 用户 |
| 3 | 本地知识库问答（RAG） | 上传文档/笔记，向量化后针对自己的资料问答 | 用户 |
| 4 | 多模型 Playground | 一个界面并排对比多个模型回答，带 prompt 模板管理 | 技术/开发者 |
| 5 | 个人 AI 助手门户（Agent） | 聊天是壳，核心是挂本地工具（文件、命令等） | 用户/技术 |
| 6 | 个人 Markdown 笔记 | 纯 Markdown 笔记库 + 以笔记为上下文的 AI 问答 | 用户 |
| 7 | 只做后端网关 | 只做 Go 统一 API 网关，前端用现成开源项目（Open WebUI 等） | 成本 |
| 8 | 不做/改现成 | fork Chatbox/LobeChat 等成熟项目，或先不立项 | 成本/商业 |

## 决策标准

1. **渐进可交付**：每个阶段独立可用，后一阶段复用前一阶段的地基
2. **实现成本可控**：从最简单的核心（聊天）起步，不一上来做 Agent
3. **技术栈契合**：全程 Go + TS 的 BS 架构不变（排除候选 7/8 的"不做 UI/不从零写"路线）

## 收敛结果

| 候选 | 判断（留 / 砍） | 理由 |
|------|-----------------|------|
| 1 极简 Chat 克隆 | **留（阶段 1）** | 是后续方向的公共地基：多会话、流式输出、API 接入、历史持久化 |
| 2 AI 搜索引擎 | 留（阶段 2） | 本质是"带联网工具的聊天"，依赖阶段 1；单独起步抓取+引用复杂度高 |
| 5 个人 AI 助手门户 | 留（阶段 3） | Agent 工具执行最难，必须有聊天地基 |
| 6 个人 Markdown 笔记 | 留（阶段 4） | 纯 CRUD + 编辑器是完整工程，与 AI 耦合弱，放最后并集成 AI 问答 |
| 3 本地知识库 RAG | 砍 | 与笔记阶段（6）功能重叠，届时可作为笔记问答的实现方式重新评估 |
| 4 多模型 Playground | 砍 | 偏开发者调试工具，与"类豆包个人助手"主线偏离 |
| 7 只做后端网关 | 砍 | 放弃自建前端，违背 Go+TS BS 架构的立项前提 |
| 8 不做/改现成 | 砍 | 用户明确要新开发；fork 路线不符合从零立项的意图 |

## 选定方向

- **首选**：阶段 1 —— 极简 Chat 克隆（地基：多会话、流式输出、多 LLM 接入、历史持久化）
- **备选**：无（用户选择分阶段路线图而非单选，后续阶段按序推进）

### 分阶段路线图

| 阶段 | 方向 | 在前一阶段上加什么 |
|---|---|---|
| 1 | 极简 Chat 克隆 | ——（地基） |
| 2 | AI 搜索引擎 | 联网抓取工具 + 流式总结 + 引用来源 |
| 3 | 个人 AI 助手门户 | 本地工具执行（文件、命令等） |
| 4 | 个人 Markdown 笔记 | 笔记库 + 以笔记为上下文的 AI 问答 |

> 阶段 2、3 可共用同一套"工具调用"框架（各自注册不同工具），此架构决策影响阶段 1 设计，须在 grill 阶段确定。
>
> **远期方向（2026-10-12 补充）**：辅助办公——起草邮件、会议纪要、写文档等。目标用户为**通用用户**（含不写代码者），非技术用户；当前四阶段为其地基。

## 待澄清的未知

- 阶段 1 的模型接入范围：只支持 OpenAI 兼容 API，还是多 provider（Claude、本地 Ollama）？
- 无登录下的数据存储方案：SQLite 单文件？会话历史保留策略？
- **工具调用框架是否统一**（影响阶段 1 架构，建议 grill 优先定）：阶段 2 的搜索与阶段 3 的 Agent 工具是同一套框架还是各自独立？
- 阶段 4 笔记的定位：独立页面，还是与聊天集成（如 @ 笔记引用）？
- 各阶段验收标准：属于 /flow-grill 产出。
