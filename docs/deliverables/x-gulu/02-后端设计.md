## 0. 部署形态与总体约定

- **单二进制**：前端 `dist/` 用 `embed.FS` 打进 Go 二进制，`/api/*` 走 API、其余路径回退 `index.html`。**同源，无 CORS**；用户"下载一个文件、双击运行、浏览器打开"即可（对通用用户受众是决定性的）。
- **监听默认 `127.0.0.1:8737`**（需求功能 #14），可用 `--addr` 覆盖；不提供 `0.0.0.0` 的默认/推荐值。
- **API 前缀 `/api`，不做版本号**（ADR-0007）：前后端同仓同发布，无第三方消费者。
- 数据目录默认 `~/.xgulu/`，可用 `--data-dir` 覆盖；`xgulu.db` 文件权限 `0600`。
- 日志目录默认 `<data-dir>/logs/`（目录 `0700`、文件 `0600`），可用 `--log-dir` 覆盖；**置空则完全不落盘**，只输出 stderr（`.gitignore` 里预留的 `/logs/` 正对应开发时 `--log-dir ./logs` 的情形）。
- 所有时间戳为 Unix 毫秒（`int64`），响应中为数字。

### 1.3 SSE 流协议（确认 ADR-0003）

`Content-Type: text/event-stream`，`Cache-Control: no-cache`，`X-Accel-Buffering: no`；每条事件一次 `Flush`（不憋包，满足 200ms 指标）；**每 15s 发 `: ping` 注释行**防中间层/浏览器空闲超时。

```
event: start       data: {"messageId":"msg_01J...","conversationId":"cnv_01J...","seq":8}
event: delta       data: {"text":"增量文本"}
event: done        data: {"finishReason":"stop","usage":{"promptTokens":812,"completionTokens":233}}
event: error       data: {"code":"upstream_timeout","message":"模型响应超时，请重试"}
event: interrupted data: {}
```

规则：

- `start` 在首个 delta 前必发（前端据此确定占位消息 id）；`seq` 与 `messageId` 先落库占位（`status=streaming`）。
- 客户端 abort（"停止生成"）→ 服务端 `ctx.Done()` → 把已累计内容以 `status=interrupted` 落库并结束响应，**不补发** `interrupted` 事件（连接已断，前端本地收口即可）；服务端主动发现上游中断时发 `interrupted`。
- `error` 事件发出前把占位消息以 `status=error` + `errorCode` 落库，`message` 是**已去行话的中文文案**，前端直接展示不再翻译。
- 单会话串行：同会话已有进行中的流 → `409 stream_in_progress`（`{"error":{"code":"stream_in_progress","message":"该会话正在生成回答，请先停止或等待完成"}}`）。

### 1.4 错误码约定

统一响应体：`{"error":{"code":"...","message":"...","field":"..."?}}`；`message` 一律去行话中文（通用用户受众），不暴露堆栈与上游响应体。

| HTTP | code | 场景 |
|------|------|------|
| 400 | `invalid_request` | 请求体不合规（含字段名与原因，`field` 指出字段） |
| 400 | `invalid_model_ref` | 会话未选定可用模型却发起请求 |
| 404 | `conversation_not_found` / `service_not_found` / `message_not_found` / `role_not_found` | 资源不存在 |
| 401 | `invalid_api_key` | 上游拒绝 key（用户侧问题，需引导去设置） |
| 409 | `stream_in_progress` | 同会话已有进行中的流 |
| 422 | `context_too_long` | 单条输入超出模型上下文（截断后仍超） |
| 429 | `rate_limited` | 上游限流 |
| 502 | `upstream_error` / `empty_response` / `models_not_supported` | 上游异常、空回答、不支持模型列表 |
| 504 | `upstream_timeout` | 上游超时（默认 60s 首包、180s 总时长，可配置） |
| 500 | `storage_error` / `internal_error` | 本地存储与内部错误 |

## 2. 数据模型

SQLite（WAL），迁移用内嵌 `migrations/NNNN_*.sql` + `PRAGMA user_version` 计数（自研 ~20 行，不引迁移库）。

```sql
-- 0001_init.sql
CREATE TABLE services (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, preset TEXT,
  base_url TEXT NOT NULL, api_key TEXT,           -- 明文存本地 0600 文件；仅本机、无登录
  models_json TEXT NOT NULL DEFAULT '[]',         -- [{"id","name"}]
  is_default INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

CREATE TABLE roles (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, system_prompt TEXT NOT NULL,
  params_json TEXT NOT NULL DEFAULT '{}',         -- {"temperature":0.3,...}
  is_builtin INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);

CREATE TABLE conversations (
  id TEXT PRIMARY KEY, title TEXT NOT NULL DEFAULT '',
  service_id TEXT REFERENCES services(id) ON DELETE SET NULL,
  model_id TEXT, role_id TEXT REFERENCES roles(id) ON DELETE SET NULL,
  last_seq INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

CREATE TABLE messages (
  id TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  seq INTEGER NOT NULL, role TEXT NOT NULL CHECK(role IN ('user','assistant')),
  content TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL CHECK(status IN ('complete','streaming','interrupted','error')),
  error_code TEXT, pinned INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  UNIQUE(conversation_id, seq)
);
CREATE INDEX idx_messages_conv ON messages(conversation_id, seq);
CREATE INDEX idx_conversations_updated ON conversations(updated_at DESC);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- 键：global_prompt, context_limit(默认"20")

-- 0002_summaries.sql（完整版启用）
CREATE TABLE conversation_summaries (
  id TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  through_seq INTEGER NOT NULL,                   -- 该摘要覆盖到第几条消息
  content TEXT NOT NULL, created_at INTEGER NOT NULL,
  UNIQUE(conversation_id, through_seq)
);
```

设计说明：

- **一条消息一行**（不是"每轮一行"）：流式增量更新同一行 `content`，中断/失败只是 `status` 变化，重试产生新行——`UNIQUE(conversation_id, seq)` 保证顺序确定。
- `messages` 不存 system prompt / 摘要：它们是**请求时构建**的上下文产物（§3 `internal/context`），不污染对话可见历史。
- **启动自愈**（崩溃恢复）：启动时把 `status='streaming'` 的消息改为 `interrupted` 并保留已存内容——否则界面会永远显示"生成中"（需求边界 #3 的延伸）。
- 崩溃恢复、迁移失败的处理：迁移失败即拒绝启动并打印明确指引，不做半迁移。
- 存量数据策略：本需求为 v0 首版，无存量；后续版本一律走 `migrations/` 递增，**禁止改动已发布迁移文件**。

## 3. 模块 / 服务边界

```
cmd/xgulu/main.go          旗标解析(--addr/--data-dir/--open)、日志初始化、迁移、自愈、装配、优雅关闭
internal/config            配置结构、默认值、数据目录定位 —— 唯一原始值来源（注入以结构体为单位）
internal/app               装配层：手写显式构造（app.New）+ App 生命周期（Run / Close）
internal/store             SQLite 连接(WAL/busy_timeout)、迁移、四类仓储、事务
internal/provider          Adapter 接口 + 三个实现 + 预置服务商表 + 模型列表探测
internal/context          上下文构建：条数截断→token 预算→摘要压缩→钉住豁免；token 估算
internal/chat              编排：发送/重新生成/编辑重发；会话级锁；增量落库；向 httpapi 发事件
internal/httpapi           路由、中间件(req_id/日志/panic 恢复)、DTO 编解码、错误码映射、SSE writer
internal/export            Markdown / JSON 导出渲染
internal/migrate           内嵌 SQL 迁移执行
internal/apperr            错误类型（code/HTTP/去行话文案）+ 统一 HTTP 映射
internal/logging           slog 构造 + lumberjack 轮转 sink、请求域 logger、ctx 传递（ADR-0008）
internal/secret            API key 包装类型：LogValue/MarshalJSON 恒输出打码值（ADR-0008）
```

**依赖方向（单向，评审检查项）**：`cmd → app → httpapi → chat → {context, provider, store}`；`apperr` / `logging` / `secret` / `config` 为底层共享内核，谁都能 import 而它们不 import 业务包。**`store` / `provider` 永不 import `chat` / `httpapi`**。该规则应由 golangci-lint 的 `depguard` 在 CI 中机器化——只写在文档里的约束不会被执行。

| 模块 | 职责 | 接缝（对外接口） |
|------|------|------------------|
| `internal/provider` | 屏蔽 OpenAI 兼容 / Anthropic / Ollama 的协议差异 | `Adapter.Stream(ctx, Request, emitDelta) (Usage, error)`、`Adapter.ListModels(ctx) ([]Model, error)`——**唯一上游协议接缝**，测试用假上游 `httptest` |
| `internal/context` | 决定"这次请求带哪些历史" | `Builder.Build(conv, msgs, settings, role) ([]Message, BuildInfo)`——纯函数（除摘要调用外），可独立测 |
| `internal/store` | 持久化，不含业务规则 | 仓储方法按实体；`store.Store` 接口便于测试替身 |
| `internal/chat` | 业务编排（顺序、锁、状态机） | `Service.Send(ctx, conversationID, content, emitFn)`——HTTP 层只做 DTO 转换 |
| `internal/httpapi` | 传输层 | 路由表 + 错误映射；不写业务判断 |
| `internal/apperr` | 领域错误 → HTTP 的唯一出口 | `apperr.Error{Code, HTTP, Message, Err}` + `errors.Is/As` 判定；handler 只 `return err`，由 `httpapi.respond(w, err)` 映射，未映射者一律 500 `internal_error` 且响应不含 err 文本 |
| `internal/secret` | 密钥的"防泄漏"表示 | `Secret` 实现 `slog.LogValuer` + `json.Marshaler`，输出恒为 `sk-****3f2a`——密钥被打进日志/响应在结构上不可能 |

### 3.1 装配与依赖注入（手写显式构造，见 ADR-0010）

**不引任何 DI 工具或框架**（原计划的 `wire` 已随其归档而弃用，见 ADR-0009「废弃说明」）：装配就是 `internal/app` 里一段按依赖顺序排列的普通 Go 代码。

```go
// internal/app/app.go（示意）
func New(cfg config.Config) (*App, error) {
    logger := logging.New(cfg)
    st, err := store.Open(cfg)                    // 打开 + WAL/pragma
    if err != nil { return nil, fmt.Errorf("打开数据库: %w", err) }
    reg := provider.NewRegistry(cfg)
    chatSvc := chat.New(st, reg, context.NewBuilder(reg), logger)
    srv := &http.Server{
        Addr: cfg.Addr, Handler: httpapi.New(chatSvc, st, cfg, logger).Handler(),
        ReadHeaderTimeout: 10 * time.Second, IdleTimeout: 120 * time.Second,
    }
    return &App{cfg: cfg, logger: logger, store: st, server: srv}, nil
}

func (a *App) Run(ctx context.Context) error   // ListenAndServe → 等 ctx.Done → Shutdown(10s)
func (a *App) Close() error                    // 逆序释放：先 server 后 store
```

装配约定（评审检查项）：

1. **装配集中在 `internal/app` 一处**；`cmd/xgulu/main.go` 只剩"解析旗标 → 迁移 → 自愈 → `app.New` → `Run` / `Close`"。业务包**不提供** `NewDefault()`、包级单例之类的"自己找依赖"入口，依赖一律由参数传入。
2. **只注入长生命周期对象**（`*store.Store`、`*slog.Logger`、`provider.Registry`、`*chat.Service`、`*httpapi.Server`）；请求级对象（SSE emitter、`*http.Request`、请求级 logger）**绝不进构造函数**，走函数参数。
3. **接口定义在使用方（依赖倒置）**：`chat` 包自己声明 `type Store interface{...}` / `type Adapter interface{...}`，由 `store` / `provider` 提供实现——这正是"测试不需要 DI 工具"的机制（`chat.New(fakeStore, fakeAdapter, logger)`）。
4. **构造函数只接收真正需要的东西**，能失败才返回 error（开 DB、读配置）；纯内存组装不返回 error。
5. **释放顺序与构造相反**：`App.Close()` 逆序关闭（先 server 后 store）。
6. **配置只从 `config.Config` 进**：各包不自行读旗标/环境变量，避免配置来源分散（与"装配是一处"同一条原则）。

**启动顺序写在 `main` 里**（装配只负责"把对象接起来"，不负责"按顺序做副作用"）：解析旗标 → 建 logger → 开 store → **跑迁移**（失败即拒绝启动）→ **启动自愈**（`streaming` → `interrupted`）→ `app.New` 装配 → Listen → `signal.NotifyContext` + `srv.Shutdown(10s)`。

**代价与兜底**：新增一个依赖要改 `internal/app` 十几行；依赖图变大后没有工具帮着看图，因此**依赖方向由 golangci-lint 的 `depguard` 在 CI 中守住**，且 `internal/app` 的 diff 一律按高风险评审（它一错就是全站性的）。好处是编译期保障基本没丢——Go 的构造函数签名本身就是类型检查，漏传参数编译不过，wire 额外提供的只是"顺序推导"。

### 3.2 HTTP 层实现约定

- **路由用 Go 1.22+ 的 `http.ServeMux` 方法 + 通配符模式**（`mux.HandleFunc("POST /api/conversations/{id}/messages", h)` + `r.PathValue("id")`），**不引 chi/gorilla**。
- 中间件手写三个：`recover` / `requestid` / `accesslog`（标准 `func(http.Handler) http.Handler` 链）。
- **SSE 刷新用 `http.NewResponseController(w).Flush()`**，不要断言 `http.Flusher`（包中间件后会静默失效）。
- `http.Server{ReadHeaderTimeout: 10s, IdleTimeout: 120s, WriteTimeout: 0}`（SSE 必须为 0，靠 per-request `context` 控超时）。

## 4. 非功能约束

- **鉴权/权限**：无。安全边界 = 只监听 `127.0.0.1` + 数据库文件 `0600`。**明确风险**：本地其他进程/同机用户可读明文 API key，这是"无登录的个人工具"的自洽代价，写入 README 提示。
- **性能**：首屏 < 1s（静态资源内嵌，无外部请求）；流式转发**不缓冲**（每次 delta 立即 Flush）；上下文构建为内存操作，目标 < 5ms（万条消息内）；`GET /api/conversations` < 50ms。
- **并发与幂等**：SQLite WAL + `busy_timeout=5000ms`，连接池 `MaxOpenConns(1)`（写串行、实现最简单，本机负载下无瓶颈）；同会话流互斥由 `internal/chat` 的会话锁保证（不同会话可并行流）；`POST /messages` 非幂等——由 409 与会话锁保证不会重复落库；消息 `seq` 在事务内 `last_seq+1` 递增。
- **日志与可观测**（详见 ADR-0008）：日志库用标准库 **`log/slog`**（不引 zap/zerolog/logrus）；**轮转交给 `lumberjack`**。输出端 `io.MultiWriter(os.Stderr, &lumberjack.Logger{...})` → JSON 同时进 stderr（终端可见）与 `<log-dir>/xgulu.log`（历史留存）；`--log-format text` 供人读；`--log-level` 经 `LevelVar` 运行期可调。
  - 轮转参数：`MaxSize=10`(MB) · `MaxAge=30`(天) · `MaxBackups=10` · `Compress=true` · `LocalTime=true`；**按大小/时间轮转，不做按级别分流**（分流会把一次请求的日志拆散）。
  - **以 `ctx` 为主传递通道**（`slog.InfoContext` + `logging.FromContext`），中间件注入请求域 logger 与 `req_id`（`crypto/rand` 生成，回写 `X-Request-Id`）；字段：`req_id/method/path/status/duration_ms/bytes/err_code`。
  - 级别约定：Info = 生命周期与每请求一行访问日志；Warn = 上游 401/429、超时、降级路径（摘要失败、自动加载模型失败）；Error = 5xx、存储失败、panic。
  - **永不记录** 请求体中的 `apiKey`、上游响应体、消息内容（隐私优先）；上游错误只记 code + HTTP 状态。密钥一律以 `internal/secret.Secret` 流转，其 `LogValue`/`MarshalJSON` 恒输出打码值——**泄漏是结构性不可能，而非靠自觉**；日志落盘后这一层是硬要求（泄漏面从终端变成了磁盘文件）。
  - 日志目录 `0700`、日志文件 `0600`，与数据库同级的本地隐私边界。
- **超时**：上游首包 60s、总时长 180s（可在设置中暴露为高级项，阶段 1 用常量）；`http.Server` `WriteTimeout=0`（SSE 需要），靠 per-request `context` 控制。

| 差异 | 前端提议 | 定稿 | 原因 |

| 预置服务商来源 | 前端硬编码预置表 | **服务端** `GET /api/services/presets` | base URL 与预置模型会变；单一来源，前端不硬编码 |

**已关闭的开放问题**（原 01-需求）：

1. **角色与全局 system prompt 的关系**：`conversation.role_id` 有值 → 用角色的 `systemPrompt` + `params`；为空 → 用 `settings.global_prompt`（若为空则不发送 system）；**两者不叠加**（叠加会让"选了角色还被全局提示词污染"，对通用用户不可解释）。详见 ADR-0006。
2. **重新生成语义**：MVP = **替换**最后一条 assistant 消息内容（复用同一 `messageId`），前端直接替换渲染。
3. **摘要压缩策略**：见 §6（触发条件与缓存规则）。
4. **工具调用框架**：阶段 1 不做，但 `internal/provider` 的 `Request` 保留 `Tools []Tool` 空字段位，阶段 2/3 决定是否统一（不预留实现，仅留扩展点）。

## 6. 上下文构建策略（完整版设计，MVP 先落前两条）

`Builder.Build` 按顺序执行，产出 `[]Message`（system → 摘要 → 钉住消息 → 最近消息）：

1. **取最近 N 条**（MVP，`settings.context_limit` 默认 20，按消息条数）。
2. **token 预算截断**（完整版）：预算 = 模型上下文窗口 − 输出预留 − system/摘要开销；估算器用启发式（CJK 每字符 ≈ 1 token、ASCII 每 4 字符 ≈ 1 token），验收允许 10% 误差，不引 tiktoken。
3. **摘要压缩**（完整版）：被截断的旧消息累积超过阈值（默认 30 条）时，调模型生成摘要写入 `conversation_summaries`（`through_seq` 记录覆盖范围，**缓存复用**：同一 `through_seq` 不重复摘要）；摘要失败则降级为直接截断，不阻塞对话。
4. **钉住豁免**（完整版）：`pinned=1` 的消息始终包含，不计入截断（但仍计入预算；若钉住内容本身超预算 → 返回 `422 context_too_long`）。
5. `BuildInfo`（含估算 token、是否压缩、是否截断）随请求记入日志，便于调试"模型为什么忘了"。

## 7. 测试边界

| 模块 | 接缝 | 典型用例 |
|------|------|----------|
| `internal/provider` | `Adapter` 接口 + `httptest` 假上游 | OpenAI/Anthropic/Ollama 三家流式解析（跨 chunk 半行 JSON、`[DONE]`、Anthropic `event:` 类型差异）；401/429/超时映射到错误码；`empty_response` 判定 |
| `internal/context` | `Builder.Build` 纯函数 | N 条截断边界（恰好 N、N+1）；预算截断不超 10% 误差；钉住消息必在结果中；摘要缓存命中不重复调用模型；摘要失败降级 |
| `internal/store` | 仓储方法（临时 SQLite 文件） | 迁移幂等（重复启动不重复执行）；`seq` 递增唯一；级联删除；启动自愈把 `streaming` 改 `interrupted` |
| `internal/chat` | 假 Adapter + 内存 store | 正常流式落库顺序（start→delta 累加→done）；abort 后 `status=interrupted` 且内容保留；上游错误 → `status=error` + errorCode；同会话并发 → 409 |
| `internal/httpapi` | `httptest.Server` | SSE 帧格式与 15s 心跳；错误码映射表逐条；`apiKey` 不出现在任何响应/日志（含导出） |
| `internal/secret` · `internal/logging` | 纯函数 / 替换默认 logger | `Secret` 的 `LogValue`/`MarshalJSON` 恒为打码值；跑完整请求后断言日志缓冲中**不含明文 key** |
| `internal/export` | 纯函数 | 单会话 Markdown 保真（消息顺序、角色标注、代码块）；全量 JSON 可被 `jq` 解析 |

> 时间相关用例（SSE 15s 心跳、首包 60s / 总时长 180s 超时、会话锁竞争）用 **`testing/synctest`**（Go 1.25 起正式可用，本项目 Go 1.26.1 具备）——虚拟时钟使这些测试瞬间完成且不 flaky，避免真等 15 秒或引入随机失败。
