# 需求：阶段 1 · 极简 Chat 克隆（x-gulu）

> 交付物 01 · 由 /flow-grill 产出 · 设计/开发阶段以本文档为输入
> 上游：[00-构想.md](00-构想.md)

## 背景与动机

自托管一个类似豆包的个人 AI 聊天工具，作为四阶段路线图（聊天 → AI 搜索 → 助手门户 → 笔记）的地基。**远期方向：辅助办公（起草邮件、会议纪要、写文档等），当前四阶段为其地基。**

动机优先级（2026-10-12 受众修订后确认）：

1. **C 学习/开源作品**：做一个 Go + TypeScript 完整 BS 项目练手并作为开源作品展示，代码结构、文档、README 要达到可开源展示水准
2. **A 数据自主**：对话历史自托管、存本地，不落在第三方服务器
3. **B 模型可及性**（原"模型自由"，权重下调）：通用用户不在乎接哪家模型，但产品须能对接常用服务：Ollama、DeepSeek、ChatGPT、豆包、Qwen、GLM 等

不做的代价：继续依赖闭源产品，数据与模型选择受制于人，且失去一个完整的练手项目。

## 目标

- 本机启动服务，Chrome 中完成多会话、流式、可持久化的多模型聊天
- **通用用户（含不写代码者）开箱可用**：选预置服务商 → 粘贴 API key → 自动加载模型即可聊天
- 模型接入覆盖 OpenAI 兼容服务、Anthropic 原生协议、Ollama 本地；内置预置：DeepSeek / ChatGPT(OpenAI) / 豆包 / Qwen / GLM / Ollama + 自定义 OpenAI 兼容
- 对话历史、服务商配置、角色全部存本地 SQLite，重启不丢
- 达到可开源展示的工程质量（结构清晰、README、基础文档）

## 非目标

以下明确排除在阶段 1 之外（对应构想文档收敛结论）：

1. 多模态（图片输入/生成）
2. 语音（输入/播报）
3. 移动端适配（仅桌面 Chrome）
4. 多用户 / 局域网共享（无登录，且默认只监听本机）
5. 主题系统（单套界面，无暗色模式/多主题切换）

另：联网搜索、Agent 工具执行、Markdown 笔记属于阶段 2/3/4，本阶段不做。**办公相关新功能（长文写作模式、按大纲生成等）不进阶段 1**——办公能力靠既有功能与完整版「角色」承载，功能演进走后续阶段。

## 用户与场景

- 目标用户：**通用用户**，包括不写代码、不碰服务器的人；开源后的潜在用户同此画像
- 典型场景 1：本机打开 Chrome，和模型多轮对话；关闭后历史仍在
- 典型场景 2：办公向使用——起草邮件、写会议纪要、让 AI 改写润色一段文字
- 典型场景 3（完整版）：为会话选择"角色"（如写作助手、翻译），以特定系统提示词与模型参数对话

## 功能需求

### MVP（阶段 1 · 第一子阶段）

| # | 功能点 | 描述 | 验收标准（可检验） |
|---|--------|------|--------------------|
| 1 | 多会话管理 | 新建、删除（二次确认）、会话列表按时间排序展示于侧边栏 | 删除弹确认框，确认后列表中消失且不可恢复 |
| 2 | 流式聊天 | 消息发送后回答逐 token 流式渲染 | 首 token 出现后 200ms 内界面可见增量内容 |
| 3 | 停止生成 | 打断进行中的流式输出 | 点击后流停止，已生成内容保留并标注"已中断" |
| 4 | 模型接入 | 预置服务商（DeepSeek / ChatGPT(OpenAI) / 豆包 / Qwen / GLM / Ollama）+ 自定义 OpenAI 兼容 + Anthropic 原生；技术上维持 C 档（OpenAI 兼容 + Anthropic 原生 + Ollama） | 预置列表中任选一个真实服务商填 key 后可完成一轮对话；自定义 OpenAI 兼容手工配置同样可用 |
| 5 | 服务商设置页 | 两入口：① **预置流程**——选服务商 → 只填 API key（Ollama 填地址）→ **自动拉取该服务商模型列表**供选择，base URL 预填、可折叠"高级设置"手动改；② **自定义（OpenAI 兼容）**——手动填服务商名称、base URL、API key、模型。key 存 SQLite，界面打码显示 | 预置流程填对 key 后模型列表自动出现且可选；改 key 无需重启，下一次请求生效 |
| 6 | 上下文（MVP） | 每次请求携带最近 N 条消息（默认 20，可配置），超限从最旧丢弃；全局 system prompt 设置页可改 | 将 N 设为 4 后发起第 6 条消息，请求体仅含最近 4 条 + 全局 system prompt |
| 7 | 会话持久化 | 历史存 SQLite，服务重启后仍在 | 重启服务后打开旧会话，消息完整 |
| 8 | Markdown 渲染 | 回答渲染 Markdown + 代码高亮，代码块带复制按钮 | 含代码/列表/表格的回答正确渲染；点击复制得到纯代码 |
| 9 | 消息重新生成 | 对最后一次输入重新请求一次回答 | 点击后产生新回答，旧回答的处理方式在设计阶段定稿（替换或保留） |
| 10 | 消息复制 | 整条消息一键复制 | 复制内容为该消息完整文本 |
| 11 | 会话命名 | 手动重命名；新会话以首条消息自动命名 | 新会话发出第一条消息后侧边栏标题更新 |
| 12 | 对话导出 | 单会话导出 Markdown；全部会话导出 JSON | 导出文件可被通用工具/脚本正常打开 |
| 13 | 空状态引导 | 未配置任何服务商时展示引导页并指向设置页，聊天输入禁用；文案去行话：`还没有连接模型 · 选一个常用服务（DeepSeek、ChatGPT、通义千问…），粘贴 API Key 就能开始` | 清空数据库后首屏出现引导页，输入框不可用，文案与上一致、无 "base URL / provider" 等行话 |
| 14 | 默认监听 127.0.0.1 | 服务默认只绑定本机回环地址 | `curl http://<局域网IP>:<port>` 不可达，`127.0.0.1` 可达 |

### 完整版（阶段 1 · 第二子阶段，建立在 MVP 之上）

| # | 功能点 | 描述 | 验收标准（可检验） |
|---|--------|------|--------------------|
| 15 | Token 预算截断（原 a） | 上下文按 token 预算截断，不同模型/服务商预算可配置 | 配置小预算后，长会话请求体 token 估算不超过预算且不超 10% 误差 |
| 16 | 旧消息摘要压缩（原 b） | 超限的旧消息由模型总结为摘要随上下文携带 | 长会话中询问仅存在于旧消息的细节，能基于摘要回答 |
| 17 | 钉住消息（原 d） | 指定消息不被截断/压缩丢弃 | 钉住首条消息后，超长会话请求仍包含它 |
| 18 | 角色 | **角色 = 系统提示词 + 模型参数（如 temperature）的封装**；可创建/编辑/删除角色，每个会话可选择一个角色；办公向预置角色（写作助手、翻译、会议纪要等） | 选择不同角色后同一问题的回答风格/随机性可观察出差异；请求体携带对应 system prompt 与参数 |
| 19 | 编辑已发消息（覆盖式） | 编辑某条已发消息并重发，该消息之后的历史被替换 | 编辑第 k 条后，会话中第 k 条之后的旧消息消失，新回答接续 |
| 20 | 全文搜索 | 跨会话搜索消息内容 | 输入关键词返回命中的会话列表，点击跳转 |

## 约束

- 技术/环境：BS 架构；Go 后端 + TypeScript 前端；数据存本地 SQLite；无登录
- 部署形态：**单二进制**——前端产物内嵌进 Go 二进制，用户下载一个文件运行即可（面向通用用户的交付要求）
- 浏览器：**承诺兼容 Chrome；其他浏览器不承诺**（Chromium 系开源套壳大概率可用，但不在承诺范围）
- 性能：本机首屏可交互 < 1s；流式转发不憋包（首 token 后 200ms 内到界面）
- 安全：默认监听 127.0.0.1；API key 存 SQLite，不进日志、前端打码展示
- 时间：不设时间盒

## 边界与异常

| # | 情形 | 预期行为 |
|---|------|---------|
| 1 | 未配置任何服务商/key | 空状态引导页指向设置页，聊天框禁用（文案见功能 #13） |
| 2 | 请求失败（401/429/超时/网络断） | 界面显示可读错误 + 重试按钮，不静默吞错 |
| 3 | 流式输出中途断开 | 保留已生成部分内容，标注"已中断"，可重试 |
| 4 | 模型返回空内容/异常格式 | 视为失败，走 #2，不按成功展示 |
| 5 | 空会话 | 只展示输入框，无历史占位 |
| 6 | 删除会话 | 二次确认弹窗，删除后不可恢复 |
| 7 | SQLite 写失败 | 错误呈现到界面，不静默丢数据 |
| 8 | 对话中修改服务商配置 | 进行中对话不受影响（沿用请求开始时的配置），新配置对后续请求生效 |
| 9 | 多处同时编辑同一服务商配置 | 后提交者生效，不做冲突提示（单人使用场景可接受） |
| 10 | 上下文截断导致模型"忘了"旧内容 | 正常行为，非异常（完整版用摘要压缩缓解） |
| 11 | 预置服务商"自动加载模型"失败（key 错 / 网络断 / 该服务商不支持模型列表接口） | 设置页该步骤显示可读错误 + 「手动填写模型」降级入口，不卡死流程 |

## 开放问题

- [x] **角色与全局 system prompt 的关系**：已定（2026-10-12 后端设计）——会话选了角色用角色，未选用全局提示词，**两者不叠加**。见 ADR-0006。
- [x] **重新生成时旧回答的处理**：已定（2026-10-12）——MVP **替换**最后一条回答（复用同一 messageId），不做版本切换。
- [x] **摘要压缩的触发与缓存策略**：已定（2026-10-12）——被截断旧消息累积超 30 条时生成，按 `through_seq` 缓存复用，失败降级为直接截断。见 ADR-0006。
- [x] **工具调用框架是否统一**：阶段 1 不做；`internal/provider` 的请求结构仅保留空字段位，阶段 2 开工前按 ADR-0005「后续跟进」重新评估。
