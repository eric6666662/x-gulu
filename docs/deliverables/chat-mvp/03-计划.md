## 任务清单

### 任务 1：骨架 + 空会话列表（第一条端到端链路）✅

> **已完成（2026-10-14，提交 `fde70ce`）**。7 条完成定义全部实测通过；实测口径与偏差见文末「变更记录」。

- **目标**：项目从"零代码"到"浏览器里看到自己数据库中的会话列表"——Go 服务、SQLite 迁移、API、Vue 前端、单二进制嵌入五条链路各打通**最薄一份**。
- **涉及层**：☑ UI ☑ 接口 ☑ 数据
- **依据**：02-后端设计 §0（部署形态/目录/日志目录）、§1.1（`GET /api/health`、`GET /api/conversations`）、§2（迁移 0001）、§3（模块与依赖方向）、§3.1（手写装配）、§4；02-前端设计 §2（api/client、stores/chat）、§4（路由）、§5；02-ui设计 §1（会话列表空态）、§2（ChatShell/ConversationList）
- **依赖**：无
- **完成定义**：
  1. `go run ./cmd/xgulu` 启动后 `curl 127.0.0.1:8737/api/health` 返回 `{"ok":true,...}`
  2. `curl 127.0.0.1:8737/api/conversations` 返回 `[]`——**数据来自真实 SQLite**（迁移 0001 已执行，`~/.xgulu/xgulu.db` 存在且权限 `0600`）
  3. 浏览器打开前端（dev 模式）→ 侧栏渲染空态「还没有会话，点上方"新会话"开始」
  4. `go test ./...` 通过：迁移幂等（重复启动不重复执行）、health handler、conversations 仓储各至少一例
  5. `go build -o bin/xgulu ./cmd/xgulu` 产出**单文件**，运行后内嵌的前端页面可打开（`/` 返回 index.html）
  6. `curl http://<本机局域网IP>:8737/api/health` **不可达**（默认只监听 `127.0.0.1`，需求 #14）
  7. 日志同时进 stderr 与 `<data-dir>/logs/xgulu.log`

> 本任务是全计划最大的一刀（横跨"从零建立工程"的所有层）。若一个会话做不完，内部按 **后端骨架 → 存储与迁移 → 前端工程与嵌入** 三步推进，但仍以本完成定义收口。

- **涉及层**：☑ UI ☑ 接口 ☑ 数据 ☑ 上游
- **依据**：01 #4 #5 #13、边界 #1 #8 #11；02-后端设计 §1.1（presets/services/probe）、§1.2、§3.3（预置表）、§1.4（`invalid_api_key` / `models_not_supported`）；02-前端设计 §2（ServiceFormModal、stores/settings §3）、§5；02-ui设计 §1（设置视图 / 引导视图）、§3（Modal）
- **依赖**：任务 1

### 任务 3：发送消息 → 流式回答（核心闭环，最小版）

- **目标**：一条消息从输入到流式渲染再到落库全通。provider 只实现 **OpenAI 兼容 adapter**；请求体暂为"全局 system（若有）+ 当前输入"，上下文留待任务 4。
- **涉及层**：☑ UI ☑ 接口 ☑ 数据 ☑ 上游
- **依据**：01 #2 #7、约束（首 token 200ms）；02-后端设计 §1.3（SSE 协议全节）、§2（消息一条一行、`seq`）、§3（provider/chat 接缝）、§7（provider 测试）；02-前端设计 §2（`api/client.streamChat`、`stores/chat`）、§6（数据流）；02-ui设计 §3（MessageRow 流式态）
- **依赖**：任务 2
- **完成定义**：
  1. 输入消息 + Enter → 用户消息立即上屏 → 回答逐 token 流式渲染、光标跟随；本机上游下**首 token ≤200ms**（需求 #2 验收）
  2. `curl -N` 手动调用能看到 `start` → `delta`×N → `done` 帧，且每条事件即时到达（不憋包）；空闲 15s 有 `: ping`
  3. 刷新页面 / 重启服务后消息仍在（需求 #7 验收）；`messages` 表 `seq` 在同一会话内唯一递增
  4. 同会话已有进行中的流 → `409 stream_in_progress`
  5. `go test`：`internal/provider` 用 `httptest` 假上游覆盖跨 chunk 半行 JSON、`[DONE]`、401/429/超时映射、`empty_response`（§7 逐条）
  6. 前端 `stores/chat` 的流式累积与 `api/client` 的多字节 UTF-8 跨 chunk 解码有测试

- **目标**：多轮对话成立——每次请求携带最近 N 条历史与全局 system prompt；设置页可改这两项，改完即生效。
- **涉及层**：☑ UI ☑ 接口 ☑ 数据
- **依据**：01 #6（验收：N=4 发第 6 条，请求体仅含最近 4 条 + 全局 system prompt）；02-后端设计 §6（策略第 1 条）、§1.1（settings 读写）、§3（`internal/context` 接缝）；02-前端设计 §5（settings）；02-ui设计 §1（设置视图 · 通用页）
- **依赖**：任务 3
- **完成定义**：
  1. 上下文条数设为 4 → 发起第 6 条消息，用假上游抓取请求体，断言**仅含最近 4 条 + 全局 system prompt**（需求 #6 验收）
  2. 全局提示词写入后，新请求的请求体首条为 system 消息；清空则不发送 system
  3. `Builder.Build` 边界测试：恰好 N 条、N+1 条、空历史、system 为空
  4. 设置页保存后无需重启生效；保存失败有 toast 且不静默

### 任务 5：停止生成 / 中断 / 失败重试

- **目标**：流可被打断、可失败、可恢复，且每种情况都有明确的状态与可读文案。
- **涉及层**：☑ UI ☑ 接口 ☑ 数据
- **依据**：01 #3、边界 #2 #3 #4；02-后端设计 §1.3（abort 语义、`error`/`interrupted`）、§1.4（错误码表）、§2（`status` 状态机、**启动自愈**）、§7（chat 测试）；02-前端设计 §6（stop/error 路径）；02-ui设计 §3（停止按钮、错误块、中断标注）
- **依赖**：任务 3
- **完成定义**：
  1. 生成中点「停止生成」→ 流停止、已生成内容保留、标注「已生成中断」（需求 #3 验收）
  2. 上游 401/429/超时/网络断 → 界面出现错误块 + 「重试」；点重试以同一输入重新发起且输入框内容不丢
  3. 模型返回空内容 → 按失败处理（`empty_response`），不按成功展示（边界 #4）
  4. **启动自愈**：流进行中强杀进程再启动，该消息状态为 `interrupted` 且内容保留（不会永远显示"生成中"）
  5. `go test`：abort 后 `status=interrupted` 且内容保留；上游错误 → `status=error` + `errorCode`；错误码映射表逐条

### 任务 8：消息重新生成（替换语义）

- **目标**：对最后一次输入重新请求一次回答，旧回答被替换。
- **涉及层**：☑ UI ☑ 接口 ☑ 数据
- **依据**：01 #9 及开放问题（**MVP = 替换最后一条 assistant 消息，复用同一 `messageId`**，不做版本切换）；02-后端设计 §1.1（regenerate）、§5
- **依赖**：任务 5（复用中断/错误处理路径与状态机）
