## 3. 交互状态

仅列关键组件完整矩阵；未列出的组件至少覆盖 默认 / hover / 聚焦 / 禁用。

### ConversationListItem
| 状态 | 行为 |
|------|------|
| 默认 | 标题单行截断 + 右侧相对时间（"刚刚 / 10:24 / 昨天"） |
| hover | 底色变 `surface-hover`，`⋯` 菜单按钮浮现 |
| 选中 | 左侧 2px 靛蓝竖条 + 底色 `surface-active`，标题不加粗 |
| 加载中 | 标题位置灰块 shimmer（首次拉取历史时） |
| 空态 | 列表为空：`还没有会话，点上方「新会话」开始` |

### MessageRow · 模型消息（流式）
| 状态 | 行为 |
|------|------|
| 生成中 | 内容逐 token 追加，末尾闪烁光标 ▌；`MessageActions` 隐藏；顶部 GenerationStatusBar 显示 `GPT-4o 生成中 •••` |
| 完成 | 光标消失，`MessageActions` 浮现（hover 触发） |
| 已中断 | 保留已生成内容，末尾接一行：`生成已中断` + 文字按钮「重试」 |
| 错误 | 不渲染空消息；在消息位插入错误块：`请求失败：{原因}。{怎么修}` + 按钮「重试」。示例：`请求失败：API key 无效（401）。请到设置检查服务商配置。` |
| 成功（toast 级） | 复制点击后按钮文字变「已复制」1.5s |

### Composer
| 状态 | 行为 |
|------|------|
| 默认 | 输入框浅描边，Enter 发送；空输入时发送按钮禁用 |
| 聚焦 | 描边变靛蓝 + 2px ring |
| 生成中 | 发送按钮变为「停止生成」（同位置、danger 描边样式），输入框仍可编辑但发送排队禁用 |
| 禁用（引导视图） | 输入框禁用，placeholder：`请先连接一个模型服务` |
| 错误 | 发送失败不丢输入框内容，输入保留待重试 |

### ModelSwitchButton（输入框下方最左）
| 状态 | 行为 |
|------|------|
| 默认 | 幽灵按钮：当前模型友好名 + `▾`，`text-secondary`；不显示裸模型 ID、不显示服务商前缀 |
| hover | 底色 `surface-hover` |
| 聚焦 | 键盘焦点环（全站统一） |
| 打开 | 按钮底色 `surface-active`，`aria-expanded="true"` |
| 生成中 | **仍可点击**（切换只对后续请求生效，不打断当前流）；点击后不改变本次回答 |
| 无可用模型 | 按钮文案 `未选择模型`，点击弹出抽屉的空态 |

### RoleSelect（模型按钮右侧，完整版）
| 状态 | 行为 |
|------|------|
| 默认 | 同款幽灵小按钮：当前角色名（默认 `默认角色`）+ 朝上的 `⌃`；**不加「完整版」徽章**——两个工具按钮同排，徽章会让行内出现两处元信息噪音；完整版标记保留在设置页「角色」tab 与本菜单首行说明 |
| hover / 聚焦 / 打开 | 与 ModelSwitchButton 完全一致（同一套视觉） |
| 展开 | 短列表用**下拉**而非抽屉：`默认角色（无）` / `写作助手` / `翻译` / `会议纪要`…，首行说明 `角色为完整版功能`；贴屏底时自动向上翻转 |
| 选中后 | 按钮文案更新为角色名；**只对后续请求生效**，进行中的流不打断 |
| 空态 | 无自定义角色时只列 `默认角色（无）` + 末项 `管理角色…`（跳设置页角色 tab） |

### ModelDrawer（模型抽屉，向上弹出）
| 状态 | 行为 |
|------|------|
| 打开 | 锚定模型按钮左缘、位于输入框**上方**；宽 320px、内容超高时内部滚动；120ms 淡入 + 6px 上移到位 |
| 分组 | 按服务商分组，组标题为服务商名（`caption` 字号、`text-muted`）；一个服务商一个分组 |
| 条目 | 友好模型名；当前选中项左侧靛蓝对勾 + 文字 `primary`，非选中项 `text-primary` |
| hover / 聚焦 | 底色 `surface-hover`；支持 ↑↓ 移动、Enter 选中、Esc 关闭 |
| 选中后 | 抽屉立即关闭，按钮文案更新；对后续请求生效（进行中的流不打断，与需求边界 #8 同口径） |
| 空态 | `还没有可用模型` + 按钮「去添加服务商」（跳设置页服务商列表） |
| 底部 | 一行文字链接 `管理服务商…`（跳设置页），与列表用 1px `border` 分隔 |
| 关闭 | 点击抽屉外、Esc、再次点击模型按钮 |
| 移动端 | ≤560px 转为贴输入框上缘的全宽面板 |

### Modal（删除确认 / 提供方表单 / 编辑确认）
| 状态 | 行为 |
|------|------|
| 默认 | 标题 + 内容 + 右对齐操作；主按钮实心靛蓝，次按钮幽灵 |
| 加载中 | 主按钮转 spinner 且禁用，防重复提交 |
| 错误 | 表单字段下方红字：`{字段}：{发生了什么 + 怎么修}`，如 `API key：必填，用于访问该提供方` |
| 删除确认文案 | `删除会话「{标题}」？` / 说明：`删除后不可恢复。` / 按钮：「删除」(danger) / 「取消」 |

### GuideView（引导视图）
- 标题：`还没有连接模型`
- 说明：`还没有连接模型 · 选一个常用服务（DeepSeek、ChatGPT、通义千问…），粘贴 API Key 就能开始`
- 主按钮：`去设置添加` ；次按钮：`查看支持的服务商`（锚到设置页服务商列表）
- 文案纪律：全程无 base URL / provider / endpoint 等行话（受众为通用用户，2026-10-12 修订）

### Toast
- 成功：`配置已保存，下一次请求生效`、`已删除会话`、`已导出 {文件名}`
- 错误：`保存失败：{原因}`（不自动消失，需手动关闭）

### 设置视图空态
- 服务商列表为空：`还没有服务商，添加一个就能开始聊天` + 按钮「添加服务商」
- 预置流程"自动加载模型"失败：步骤内显示 `模型列表加载失败：{原因}` + 按钮「重试」+ 文字按钮「手动填写模型」（降级，对应需求边界 #11）

## 5. 美学方向

> Full 模式。视觉主张与色板已由用户在三个候选中拍板（浅色开发者工作台），完整定义沉淀于 `docs/设计稿.md`，此处摘要：

- **视觉主张**：一台安静、清爽的工具——冷调灰白底、中性灰阶、唯一靛蓝强调；像 Linear/Vercel 文档的浅色质感，第一印象是"干净、专注、没有干扰"，通用用户（含不写代码者）可无压力上手。（2026-10-12 受众修订，详见设计稿。）
- **色板**：`#FAFAFB` 画布 · `#1A1A1E` 墨色 · `#4F46E5` 靛蓝（唯一强调色）· `#E5E5EA` 描边 · `#1E1E2E` 代码深底 · `#DC2626` 危险色。
- **字体排印**：系统 UI 字族（`system-ui`）承担全部界面文字；等宽字族（`ui-monospace` 系）只用于代码块与数据。字阶 12/13/14/16/18/24；正文 14px/1.7，消息行宽 ≤ 760px。
- **结构即信息**：边框只出现在侧栏/顶栏/输入框这些真实边界上；消息流内部不用框线分隔，靠间距与角色排版区分。
- **动效**：用户触发的动效保留（模态 120ms 淡入、发送过渡），唯一非用户触发的编排元素是**流式打字光标**——这是全站记忆点；无进场动画、无滚动淡入；`prefers-reduced-motion` 下光标不闪、过渡归零。
- **文案基调**：按钮/动作用用户语言且全程同词（发送 → 已发送；删除会话 → 已删除会话）；错误 = 发生了什么 + 怎么修，不道歉不模糊；空态是行动邀请（`还没有会话，点上方「新会话」开始`）。
- **反"AI 味"自查记录**：
  1. 奶油米白 + 衬线 + 陶土 ✗ 避开（选冷灰白 + 无衬线）
  2. 近黑底 + 荧光点缀 ✗ 避开（需求无主题系统，用户在浅/暗中拍板**浅色**）
  3. 报纸风 ✗ 避开（圆角 6-10px，正常密度）
  4. SaaS 卡片套 ✗ 避开——**模型消息不做气泡卡片**，直接排版成文稿（阅读友好）；仅用户消息用浅灰块右对齐。这是与"聊天软件默认双方气泡"拉开的关键选择
  5. 模板装饰件 ✗ 避开（无眉标、无中点串、按钮无 "→"）
  - 需求指定沿用项：靛蓝 `#4F46E5` 为强调色（用户从候选预览中拍板，锁定）；`system-ui` 字族为技术工具的中性务实选择，非偷懒默认。

## 6. 布局与关键交互流程

### 布局（桌面，仅 Chrome）

```
┌────────────┬────────────────────────────────────────┐
│ 260px 侧栏  │ 52px ChatTopBar（标题 · ⋯）               │
│            ├────────────────────────────────────────┤
│ [新会话]    │                                        │
│ [搜索…]↑全  │      MessageList（内容居中 ≤760px）       │
│            │      用户消息：右对齐浅灰块                │
│ 会话1 ▓选中 │      模型消息：左对齐无框文稿               │
│ 会话2      │      代码块：深色 #1E1E2E + 复制           │
│ 会话3      │      …滚动…                              │
│            ├────────────────────────────────────────┤
│            │ GenerationStatusBar（生成中/已中断）      │
│ ⚙ 设置     │ Composer（≤760px 居中，sticky 底部）       │
│ 导出全部    │ ┌────────────────────────────────────┐ │
│            │ │ [输入…                            ] │ │
│            │ │ [DeepSeek-V3 ⌃] [默认角色 ⌃] [发送] │ │
│            │ └────────────────────────────────────┘ │
└────────────┴────────────────────────────────────────┘
        ↑ 点击最左「DeepSeek-V3 ⌃」时，抽屉从 Composer 上缘向上展开：

                            ┌──────────────────┐
                            │ DeepSeek         │
                            │  ✓ DeepSeek-V3   │
                            │    DeepSeek-R1   │
                            │ Ollama（本机）    │
                            │    qwen2.5:7b    │
                            ├──────────────────┤
                            │ 管理服务商…       │
                            └──────────────────┘
                            [DeepSeek-V3 ⌃] [默认角色 ⌃] [发送]
```

- 设置视图：主区整体替换（侧栏保留），表单内容 ≤ 720px 左对齐。
- 引导视图：主区居中空态，Composer 禁用态保留可见（让用户看到"差一步"）。
- 消息区新消息到达时自动滚底；用户上滚时暂停，出现「回到底部」浮钮。

**消息列与输入框的水平对齐（硬性规则）**：MessageList 与 Composer 共用同一个 ≤760px 居中列，四边严格重合——用户消息块右缘 = 代码块右缘 = 输入框右缘，模型消息文字左缘 = 代码块左缘 = 输入框左缘。滚动条不得破坏这条对齐：

- 消息滚动区用 `scrollbar-gutter: stable`（内容长短都预留右侧沟槽，滚动条出现/消失时列不横跳），滚动条宽度用 `.messages::-webkit-scrollbar { width: var(--scrollbar-w) }` 固定为 **8px**（`.scroll-bottom` 浮钮也按 `calc(50% - var(--scrollbar-w) / 2)` 同轴）。
- 输入区 `.composer-wrap` 与 `.status-bar` 右侧内边距 = 常规内边距 + `--scrollbar-w`，即与消息区**内容盒完全重合**；因此列居中（宽窗）与列铺满（窄窗）两种情形下都对齐，与 OS 滚动条是叠加式还是占位式无关。
- 反例（勿用）：只用 `scrollbar-gutter: stable both-edges` —— 宽窗下恰好对齐，但窄窗下列铺满宽度时，左侧沟槽会把文字推右 8px。

### 关键流程

1. **发送 → 流式**：输入 → Enter/点发送 → 用户消息立即上屏 → GenerationStatusBar 变「生成中 •••」→ token 流式追加（光标跟随）→ 完成：光标消失、动作浮现、状态栏清空。
2. **停止**：生成中点「停止生成」→ 流关闭 → 已生成内容保留 + `生成已中断` 标注 + 「重试」。
3. **失败重试**：错误块「重试」→ 以同一输入重新发起；输入框内容不丢。
4. **重新生成**：完成态模型消息 hover → 「重新生成」→（MVP 定为）**替换当前回答**，见待确认点。
5. **未配置引导**：启动检测服务商为 0 → 引导视图 →「去设置添加」→ 设置页 → 选预置服务商 → 填 API key → 自动加载模型列表并勾选 → 保存 → toast `配置已保存，下一次请求生效` → 返回聊天可用。
6. **对话中改配置**：不打断进行中的流；保存后仅 toast 提示，下一次请求生效（与需求边界 #8 一致）。
6a. **切换模型**：输入框下方最左「模型按钮」显示当前模型的**友好名**（如 `DeepSeek-V3`，不显示裸模型 ID、不重复服务商前缀）→ 点击向上弹出模型抽屉（按服务商分组，当前项打勾）→ 选中一项 → 抽屉关闭、按钮文案更新 → **只对后续请求生效**，进行中的流不打断（与需求边界 #8 同口径）。生成中按钮仍可点击。抽屉底部「管理服务商…」跳设置页。
7. **删除会话**：`⋯` → 删除 → 确认模态 → toast `已删除会话` → 侧栏移除，落到最近一个会话或空态。
8. **完整版 · 角色**：输入框下方工具条右侧 `角色 ⌃` 选择本会话角色；已选角色名显示在该按钮上（**顶栏不再显示角色名**）；角色与全局 system prompt **不叠加**，选了角色就用角色（ADR-0006）。
9. **完整版 · 编辑消息**：hover「编辑」→ 文本进入可编辑态 → 发送 → 确认模态提示 `将删除该消息之后的 {n} 条消息` → 覆盖后续历史。
10. **完整版 · 搜索**：侧栏搜索框输入 → 下拉展示命中会话（高亮关键词）→ 点击跳转并定位消息。

## 7. 原型说明

已产出 **`02-ui原型.html`**（2026-10-14，单文件 HTML + CSS + 原生 JS，标注"一次性原型，非生产代码"，不含业务逻辑与真实请求）。浏览器直接打开即可，顶部「原型控制条」切换场景：

| 控制条按钮 | 覆盖内容 |
|------------|----------|
| 聊天 | 用户消息气泡 / 模型消息文稿式排版 / 深色代码块 + 复制 / 消息动作条 |
| 模型抽屉（任意场景） | 输入框下方最左模型按钮 → 向上弹出抽屉（服务商分组、当前项打勾、空态、底部「管理服务商…」） |
| 角色选择（任意场景） | 模型按钮右侧的角色按钮 → 向上翻转的下拉（默认角色 / 写作助手 / 翻译 / 会议纪要 + 首行「角色为完整版功能」说明 + 末项「管理角色…」） |
| 流式生成中 | 打字光标 ▌、状态栏「生成中 •••」、「停止生成」按钮 |
| 已中断 | 保留已生成内容 + `生成已中断` + 「重试」 |
| 请求失败 | 错误块 `请求失败：API key 无效（401）。请到设置检查服务商配置。` + 「重试」 |
| 新会话（空） | 空消息列表 + 输入框（无历史占位，边界 #5） |
| 未配置服务商 | 引导视图 + 输入框禁用态（placeholder「请先连接一个模型服务」）+ 侧栏空态 |
| 设置 / 设置 · 无服务商 | 服务商表格（key 打码尾四位）、通用页（全局提示词 + 上下文条数）、服务商空态 |
| 模态：添加服务商 / 删除会话 | 双入口表单（预置流程三步 + 自动加载模型 + Ollama 加载失败降级 + 自定义）、删除二次确认 |

其他可交互项：会话 `⋯` 菜单（重命名 / 导出 / 删除）、模型抽屉、角色下拉（完整版占位）、导出全部、Toast、复制按钮「已复制」。手机宽度（≤900px）侧栏转为抽屉。

**原型暴露并已修正的问题**（结构层规格无变化，仅实现细节）：
1. `.scrim` 作为 grid 子元素会占一列，导致主区被挤窄 → 桌面端 `display:none`；
2. `.guide` 的 `display:flex` 压过 `hidden` 属性，引导视图常显 → 全局 `[hidden] { display:none !important }`；
3. 「重试」原会同时渲染完整答案与流式答案 → 改为原地把失败消息替换为流式消息；
4. 原型阶段补全的色值（Toast 深底、错误块三色、停止生成按钮描边）已回写 `docs/设计稿.md`；
5. 消息文字相对输入框**左偏 7.5px**（15px 经典滚动条 ÷ 2）→ 按第 6 节对齐规则改为 8px 细滚动条 + `scrollbar-gutter: stable` + 输入框右侧镜像内缩；已在 1440 / 1200 / 1000 / 860 / 420px 五档宽度实测，左缘偏差 0、右缘偏差 0。
