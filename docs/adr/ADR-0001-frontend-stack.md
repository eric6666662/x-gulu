# ADR-0001: 前端技术栈选型（Vue 3 + Vite + 轻依赖组件策略）

> 状态：已接受 · 产出：flow-design-frontend（2026-10-12）· 关联：docs/deliverables/chat-mvp/02-前端设计.md

## 背景

阶段 1（极简 Chat 克隆）前端从零起步。约束：TypeScript、与 Go 后端配合的 BS 架构、02-ui设计已定完整视觉规范（浅色开发者工作台）、受众为通用用户、项目动机 C（学习/开源作品）优先——选型要有生态与可借鉴性。不决策的代价：各文件各写各的，测试与构建无法统一。

## 决策

- 框架：**Vue 3**（`<script setup>` + Composition API）+ **Vite** + TypeScript。
- 组件策略：**自研组件 + 无样式底座 Reka UI**（只取无障碍行为，不取视觉）。
- 样式：**原生 CSS + CSS 变量**承载设计稿 token，不用 Tailwind/CSS-in-JS。
- 渲染：**markdown-it（`html:false`）+ highlight.js**。
- 测试：**Vitest + @testing-library/vue**。
- 新增依赖仅此清单，其余不引。

## 权衡

- **React 18**：LLM 聊天类开源参考最多，放弃——用户在三候选中明确选 Vue 3；Vue 中文生态对"开源面向通用用户"也有优势。
- **Svelte 5**：心智最简，放弃——生态与可借鉴实现最少，与动机 C 的"开源作品展示"不匹配。
- **完整组件库（shadcn/ui 等）**：开发快，放弃——视觉需大量覆写才能贴合设计稿，且与"轻依赖"策略冲突。
- **纯自研（零底座）**：完全可控，放弃——焦点陷阱/键盘导航等 a11y 细节工作量大且易错，Reka UI 无样式底座恰好只补这一块。
- **shiki 代码高亮**：效果更好，放弃——异步加载与体积不值（需求只要求代码高亮 + 复制）。

## 后果

- **正面**：视觉 100% 贴合设计稿；依赖面小、供应链风险低；测试栈与构建同构零配置。
- **负面 / 代价**：通用组件（模态、下拉、表单校验）需自研组装；a11y 依赖 Reka UI 的覆盖范围。
- **后续跟进**：新增任何依赖须过"轻依赖"审查并更新 02-前端设计 §1；若 Reka UI 维护停滞，评估替代底座（可逆，接口只经 `components/ui/*` 暴露）。
